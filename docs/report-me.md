# 记账系统接口测试报告

## 一、测试概述

本次测试针对记账系统后端接口进行功能验证，通过 Swagger 在线接口文档逐个调用接口，验证账单记账、预算管理、自然语言查账、小票识别四大模块的接口可用性、参数校验逻辑与返回结果正确性，并记录发现的服务端缺陷。

### 1.1 测试环境

| 项目 | 内容 |
| --- | --- |
| 接口基础地址 | `http://127.0.0.1:8000` |
| 测试工具 | Swagger 在线接口文档（Try it out / Execute） |
| 接口风格 | RESTful，请求/响应数据格式为 JSON |
| 金额单位 | 整数，单位为「分」，字段名以 `_cents` 结尾 |
| 时间格式 | 入参为 ISO 8601 带时区，接口返回 UTC 时间 |
| 字段命名 | snake_case |

### 1.2 测试范围

| 模块 | 包含接口 |
| --- | --- |
| 账单（记账）模块 | 保存账单、账单列表查询、分类统计、删除账单、一句话记账解析 |
| 预算模块 | 新增/修改预算、查询月度预算、删除预算 |
| 查账模块（自然语言查询） | 解析查账问题、一句话查询并返回结果 |
| 小票识别模块 | 上传小票/支付截图，OCR 解析生成账单草稿 |

---

## 二、测试用例汇总

### 2.1 账单（记账）模块

| 序号 | 接口路径 | 请求方式 | 响应码 | 测试结论 |
| --- | --- | --- | --- | --- |
| 1 | `/transactions` | POST | 201 | 通过：成功新增一笔餐饮账单（35 元，午饭，楼下快餐店），数据持久化到数据库 |
| 2 | `/transactions` | GET | 200 | 通过：成功查询账单列表，可读取已新增的记账记录，分页参数（limit、offset）正常 |
| 3 | `/stats/category` | GET | 200 | 通过：成功按消费类别统计支出金额，分类统计计算功能正常 |
| 4 | `/transactions/{transaction_id}` | DELETE | 204 | 通过：按 id 删除账单成功；接口设计为 id 不存在时返回 404 |
| 5 | `/transactions/parse` | POST | 422 | 负面用例通过：参数校验拦截正常，非法/异常参数返回 422；正向解析未调通，待复测 |

#### 典型请求示例

**POST /transactions（新增账单）**

```json
{
  "category": "餐饮",
  "amount_cents": 3500,
  "note": "午饭",
  "occurred_at": "2026-11-20T12:00:00+08:00",
  "merchant": "楼下快餐店"
}
```

## 三、缺陷（Bug）清单

| 编号 | 接口 | 现象 | 严重程度 | 说明 |
| --- | --- | --- | --- | --- |
| BUG-01 | `POST /query/parse` | 返回 500 Internal Server Error | 高 | 自然语言解析查账问题时服务端报错，需排查后端解析逻辑与依赖服务 |
| BUG-02 | `POST /query/ask` | 返回 500 Internal Server Error | 高 | 一句话查询并返回结果时服务端报错，与 BUG-01 可能同源，需一并排查 |
| BUG-03 | `POST /transactions/parse` | 正向请求返回 422 | 中 | 一句话记账解析接口参数校验未通过，需核对入参字段名与格式要求后复测 |

## 四、测试结论

### 4.1 统计结果

| 统计项 | 数量 |
| --- | --- |
| 测试接口总数 | 10 |
| 通过接口 | 7 |
| 不通过接口 | 2 |
| 待复测接口 | 1 |

### 4.2 总体评价

- **功能正常**：账单的新增、列表查询、分类统计、删除；预算的新增/修改、查询、删除；小票图片上传与草稿生成链路运行正常。
- **存在缺陷**：自然语言查账链路（解析、提问两个接口）均返回 500 服务端错误，需后端修复后进行回归测试。
- **待确认**：一句话记账解析接口入参字段要求需与后端确认，修复/确认后补充正向用例复测。

### 4.3 后续建议

1. 优先修复 `/query/parse` 与 `/query/ask` 的 500 错误，修复后重新执行查账链路回归测试。
2. 核对 `/transactions/parse` 的请求字段名与格式规范，补充正向解析用例。
3. 补充异常场景测试：上传非图片文件、超大文件、空文件；删除不存在的 id；空参数、特殊符号入参等边界用例。
4. 完善接口错误码与错误信息，便于前端定位问题。
